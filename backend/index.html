STAR AI 외부 호출과 DB 트랜잭션 충돌 해결
상황식전 혈당 예측은 FastAPI AI 모델 호출 결과를 DB에 저장하는데
AI 호출이 트랜잭션 내부에 있어 수 초의 추론 대기 동안 DB 커넥션을 계속 점유
A/B 비교 예측은 음식 2개를 병렬 호출해 점유 가중 → 커넥션 풀 고갈 위험
행동PredictionService에서 @Transactional을 제거해 AI 호출을 tx 밖에 두고
DB 조회·쓰기만 PredictionTxHelper의 짧은 tx로 분리
savePrediction은 detached User 대신 getReferenceById 프록시를
새 tx에서 발급해 cascade 변경 시 silent regression을 차단
병렬 호출은 전용 asyncExecutor + MdcTaskDecorator로 correlationId(MDC)를 워커에 전파
결과커넥션 점유 시간을 AI 추론 시간만큼 단축해 동시 예측에도 고갈 없이 안정 처리
async 워커가 각자 프록시를 가져 동시성 안전 + 단일 correlationId로 로그 추적성 확보

STAR n8n · Flyway 스키마 충돌 해결 (DB 환경)
상황워크플로우 도구 n8n이 backend와 같은 Postgres DB를 공유하며 테이블을 자동 생성
그로 인해 Flyway 마이그레이션과 스키마 충돌로 BE 기동 실패
행동n8n 컨테이너에 DB_POSTGRESDB_SCHEMA=n8n을 지정해 별도 schema로 격리하고
postgres init의 중복 스키마 스크립트를 제거
Flyway는 db/migration 단일 경로로 통일해 baseline을 정리
결과BE(public)·n8n(n8n schema)이 한 DB를 충돌 없이 공유, 마이그레이션 일관성 확보
